# 로딩 직후 UI 이미지 교체 검사

- 사용자 증상: Codex 내부 보기에서 로딩 직후 로비 하단이 검게 깜빡이고, 인게임 첫 진입에서도 한 번 발생.
- 실제 증상이 사라졌다는 시각 검증은 아직 하지 않았다.
- 사용 중인 기존 탭의 콘솔에서 수집한 오류/경고는 없었다. 기존 탭의 진행 상태는 변경하지 않았다.

## 코드로 재현한 문제

`web/ui/scene-renderer.js`의 `composeSliceBitmap()`은 PNG 인코딩을 마치면 blob URL을 바로 반환한다. `applySliceBitmapUpgrade()`는 그 URL 이미지의 디코드 완료를 기다리지 않고 기존 `border-image`를 제거한다. `applyShineEffect()`의 합성 마스크도 같은 준비되지 않은 URL을 사용한다. `_whenRenderResourcesReady()`는 합성 이미지 준비를 대기하지 않는다.

하단 배경과 스타트 버튼은 둘 다 이 9-slice 합성 경로를 사용한다. 이 경로에 준비되지 않은 이미지가 노출될 수 있음은 확인했지만, 사용자가 본 검은 프레임과의 직접적인 인과관계는 화면 대조 전까지 확정하지 않는다.

## 제안 수정

`renderer-decode.proposed.patch`는 기존 함수 두 곳에 총 8줄을 추가한다.

1. 합성 URL을 `Image.decode()`까지 완료한 후 반환한다. 배경과 광택 마스크가 같은 준비 완료 Promise를 공유한다.
2. UI 공개 시 시작된 합성 이미지들의 준비 완료도 기다린다.

레이아웃·색·반복 광택·애니메이션 수치는 바꾸지 않는다. 2026-11-15 사용자가 “이번 오류 부분만 직접 수정”을 명시적으로 승인하여 실제 렌더러의 두 부분에만 적용했다.

## 검사

`node tests/ui_slice_decode_check.mjs`는 실제 함수들을 추출해 디코더를 의도적으로 지연시킨다. 수정 전 원본은 `Existing image removed before the replacement was decoded`에서 실패했다. 제안 패치를 적용한 임시 복사본과 실제 수정본은 기존 이미지 유지·UI 공개 대기·캐시 공유 검사를 통과했다.

별도로 게임 셸의 기존 사전 로딩 대상에 `Ingame`을 추가했다. 이전에는 네비게이션 화면들과 전환 커튼만 사전 로딩했다.
