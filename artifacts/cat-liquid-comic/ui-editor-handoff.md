# 고양이 액체 이야기 — UI Editor 연결 명세

2026-11-15. 현재 제작본은 `revision-03/`의 **무문자 손그림 만화 2페이지/8컷과 순차 스탬프 GIF**다. 박사의 연구 → 실험 사고로 고양이 세계 진입 → 컵고양이·박스고양이와 만남 → 같은 색 차원문의 반응 관찰 → 인간계 발견 → 함께 모험을 떠나는 줄거리다. 이전의 영화풍 3D와 긴 몸 시안은 보관 기록이다. 현재 게임 실행 흐름은 수정하지 않았다. `resources/story/cat-liquid-intro.json`은 제작 명세이며 아직 런타임에서 읽지 않는다.

## UI Editor에 추가할 내용

- 기본 캔버스는 기존 게임과 같은 393×852. 한 화면에 4컷을 왼쪽 위 → 오른쪽 위 → 왼쪽 아래 → 오른쪽 아래 순서로 하나씩 찍히듯 추가한다. 이전 컷은 계속 남아 있어야 한다.
- 이야기 씬 2개를 제작한다. 제안 이름은 `StoryIntro01`, `StoryIntro02`이며, 생성된 실제 sceneUuid로 배선한다.
- 제목·부제·대사·내레이션·컷 번호·효과음 글자·텍스트 버튼을 추가하지 않는다. JSON의 `number`는 제작 순서 메타데이터이며 화면에 그리지 않는다.
- 이미지 레이어는 `src/assets/story_cat_liquid_panel_01.webp`부터 `_08.webp`를 각각 사용한다. 순차 등장에는 개별 컷이 필요하다. 완성 4컷 원화인 `story_cat_liquid_page_01.webp`, `_02.webp`는 정적 원화 보관용이며 개별 컷과 중복 로드하지 않는다.
- 사진 영역은 가로세로 비율을 보존한다. 각 컷 원화는 500×756이다. 잘라내는 cover 대신 contain으로 배치한다. 캐릭터의 귀·발이 잘리지 않도록 한다.
- 내비게이션은 글자 없는 다음/건너뛰기 아이콘으로 제작한다. 이번 GIF에는 컨트롤을 그리지 않았다. 이벤트 이름·stableId는 UI Editor가 publish한 결과를 사용한다. 게임 코드에서 먼저 임의로 발명하지 않는다.
- 텍스트가 없으므로 새 폰트가 필요하지 않다.
- 이미지 크기·배치·회전은 JSON의 `motion.layout`, `imageWidth/Height`를 사용한다. 테두리/여백도 같은 명세에 있다. 원본 이미지를 불필요하게 자르지 않는다.
- 각 컷은 240/1320/2480/3640ms에 한 번 등장한다. 200ms 동안 1.16 → 0.96 → 1.015 → 1배로 정착하고 작은 회전·Y 이동과 120ms 타격선을 사용한다. 명세의 전체 keyframe을 참고한다. 이전 컷과 화면 전체를 흔들거나 밝기 변화시키지 않는다.
- 이 연출은 각 이미지 레이어의 등장 효과로 UI Editor에서 제작한다. 회전/배율이 기존 레이아웃 transform을 덮어쓰지 않도록 합성한다. 새 런타임 함수나 임시 HTML 팝업으로 우회하지 않는다.

## 흐름

기존 스플래시 로딩을 완료한 뒤 분기한다. 조건의 의미는 아래와 같으며, UI Editor의 실제 분기 키와 publish 버튼 이벤트가 확보되면 기존 호스트의 조건·scene:enter 훅에 연결한다.

1. 이 브라우저에서 이야기를 끝까지 보거나 건너뛴 이력이 없으면 1페이지를 연다.
2. 첫 페이지의 다음 아이콘은 2페이지를 연다. 시간에 따라 자동으로 넘기지 않는다.
3. 마지막 페이지의 진행 아이콘은 완료 표시를 저장하고 기존 로비로 이동한다. 스테이지를 자동 시작하거나 하트를 소비하지 않는다.
4. 어느 페이지에서든 건너뛰기 아이콘을 누르면 완료 표시를 저장하고 기존 로비로 이동한다.
5. 이후 입장에서는 기존 스플래시 → 로비 경로를 사용한다.
6. 이미지가 먼저 디코드된 뒤 페이지를 공개한다. 기존 `scene:enter.waitUntil`과 공개 전환 API를 사용한다. 소스·계약·흐름 변경 뒤 캐시 버전도 확인한다.
7. GIF는 확인용으로 각 6.4초씩 두 페이지를 자동 반복한다. 실제 게임은 페이지당 등장 1회만 실행하며, GIF의 자동 페이지 전환·반복을 도입 정책으로 복사하지 않는다.

게임 이동·카메라·퍼즐 배치·타이머·재화 규칙을 바꾸지 않는다. 완료 표시는 스테이지 진행도와 분리하고 기존 저장 프리픽스를 사용한다.

## 현재 제약과 필요한 조치

`SCENES.md`와 현재 publish 산출물에는 이야기 씬·다음·건너뛰기 이벤트가 없다. `publish-report.json`의 errors는 0개이고 `scene-flow-changes.json`은 없다.

AGENTS.md와 `.codex/skills/ui-editor-game/SKILL.md` §1은 `*.contract.json`, `scenes-index.json`, `scene-flow.json`을 읽기 전용으로 지정한다. 같은 스킬 §0은 “SCENES.md 에 없는 이벤트/키가 필요 — 임의 생성 금지, ui-editor 에서 추가해 달라고 요청”하도록 규정한다.

따라서 위 씬·버튼·흐름을 UI Editor에서 추가해 publish하거나, 이번 이야기 도입 작업에 한해 새 씬·이벤트·흐름의 직접 생성 예외를 사용자에게 승인받은 뒤 실제 게임 연결을 진행해야 한다. 이전 승인은 팝업 배경 수정에 한정되어 있다. 임시 HTML 팝업이나 수동 씬 전환으로 우회하지 않았다.

- 이 그림은 원본 메시·셰이더의 재렌더링이 아니다. 최종 그림체와 타격감, 실제 UI 표시 확인은 사용자 확인 대상이다.
