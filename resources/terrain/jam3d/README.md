# jam-3D terrain resources

Source project: `/Users/al02501031/Documents/Codex/2026-09-09/https-git-linecorp-com-sujeong-min/jam-3D`.

Only terrain assets and terrain data are copied here. The source project is unchanged.

- `wall.fbx` and `wall1.png`: terrain tile model library and its texture atlas.
- `wall1_soft.png` and `wall1_soft.source.json`: the retained earlier variant, with green pixels at 82% saturation and 97% value. It is no longer the active terrain palette.
- `wall1_lobby.png` and `wall1_lobby.source.json`: the current terrain atlas, generated by `tools/soften_terrain_grass.py --lobby`. It matches the mean grass palette to the lobby's `(0.46, 0.62, 0.32)` color while preserving the source texture pattern using a constant HSV hue shift and saturation/value ratios. The target accounts for the existing terrain tint. No flat color fill is used. Alpha and non-green cliff/rock pixels remain byte-identical; the source atlas remains unchanged. Metadata records the palette, reference region, source/output hashes and coefficients. `tests/terrain_grass_texture_check.py` checks the retained brightness pattern within 8-bit rounding, mean palette and non-green pixels.
- `floor1.png`: terrain floor texture.
- `flower_white.obj`, `flower_white.mtl`, `texture.png`: terrain flower decoration.
- `map_level_catalog.json`: seven source terrain layouts, including baked per-cell mesh data. The source `Main.tscn` selects level 3.
- `rules.json`: source wall tile selection rules and model names. No source addon is enabled here.
- `wall_material.tres` and `floor_material.tres`: serialized materials using the source textures and source filtering/roughness settings. Terrain tint is `(1, 0.92, 1)`, a local adjustment from the user's comparison screenshot; the original source material is white. Global lighting and the cat materials are unchanged. The texture import parameters use the source's VRAM compression and generated mipmaps.
- `terrain_library.tres`: a native Godot MeshLibrary containing 54 source tile/rotation variants and the corrected neighbor selection rules described below. Uniform XYZ scaling preserves the source height/width ratio of approximately `0.65734855` (height `1.3146971` for a two-unit cell), replacing the earlier compressed ratio of `0.25`. Source UVs and triangle topology are retained, with seam corrections baked into vertex positions and plateau normals.
- `flower_material.tres`: the source flower atlas with alpha scissor at `0.5`, disabled backface culling, and source filtering/roughness. Native `flower_white.obj` instances use density `0.7` per unit-cell surface area (increased from the source's `0.2`), scale `0.3–0.5`, and up to seven degrees of tilt. The shared flower/grass sampler uses actual nearly level terrain triangles, tests eight footprint points on the grass, and reserves room inside the cell. Layout rebuilds produce the same placements.

The source camera, environment, background image layers, GameFlow, tray, character scripts, autoloads, and game rules are not imported.

The map catalog's original asset path is retained as source data. The copied FBX is available at `res://resources/terrain/jam3d/wall.fbx`.

Integration: `main_scene.tscn` assigns the library to `LevelManager.terrain_library` and uses `terrain_floor_tile.tscn` for the source floor texture. The existing `_build_obstacle_visuals()` evaluates source neighbor rules against Water Yang's current blocked cells. A native GridMap batches exterior grass/cliffs; existing obstacle cells retain individually removable meshes named `Obstacle_x_y`. There are no added physics shapes or writes to the gameplay grid. Removing an obstacle also refreshes adjacent terrain pieces. Existing decorations retain their XZ placement and their original Y offsets relative to the grass surface. Lobby terrain is unchanged.

`tools/build_terrain_library.gd` rebuilds the library with Godot 4.7.2. The source catalog has a concave `middle_right_top_point`, but its raw-FBX alias maps to a full cliff and creates a false internal drop of approximately `0.1134` cell at a connected edge. This integration instead uses the source `middle_left_top_point` cap rotated -90 degrees. Vertices within `0.005` cell of a cell edge snap to that boundary before the shared bevel correction below; nearly upward plateau normals align to `UP`. Corrections and flower-sampling triangles are baked together; gameplay does not rebuild or edit the source mesh data. The seam check measures joined surface coverage and height, while rendered appearance remains subject to user review.

The `middle_top_open` rule also used the four-concave-corner alias even though both bottom diagonals are filled. It now uses the source two-corner cap `middle_pioint_single7` rotated 180 degrees, leaving its joined bottom edge flat. The separate all-diagonals-open rule still uses the four-corner cap. The copied source `rules.json` remains unchanged; fixes are applied when generating the native library.

Three-neighbor caps now use sixteen canonical rules: four orientations times the two relevant filled-side diagonals. Diagonals beyond the exposed side cannot force an incorrect fallback with an extra notch. The catalog's ramp-like connector meshes use the original level `straight` mesh instead. Joined bevel edges snap to the straight mesh's five reference rings, including positions and normals; exposed cliff interiors retain their source geometry. The seam check covers all adjacent pieces on the hand layout and 237 stages, including fully filled 2×2 corners. Flower/grass sampling is baked from the corrected surface, so small placement/count changes are expected while density, spacing, poses, palette and wind remain the same.

Mirrored source transforms require triangle winding and tangent handedness to be reversed when baked into vertices. Without this correction, five variants (`corner_left_bottom_end_0`, `corner_right_top_end_0`, `middle_pioint_single10_0/90`, and `middle_pioint_single8_90`) had downward-facing triangles and their grass tops were culled, leaving flowers over apparent empty blocks. The generator corrects reflected transforms without changing vertices, UVs, normals, heights, material culling, or decoration sample order. The seam check additionally verifies nine upward-facing core samples in each of all 54 library variants; two-sided boundary rays alone do not detect this failure.

Ingame and lobby grass clumps retain the original central grass UV region, UV scale `(1, 1)`, tint `(1, 0.92, 1)` and `grass_use_texture_color=true`. They sample the same recolored `wall1_lobby.png` atlas as the terrain, keeping its texture detail. The thin green outline, upward lighting normal and native terrain geometry/UVs remain. The lobby lawn and cliff lip use the same `lobby_ground_depth_fade.gdshader`, with `grass_world_uv=true` and world XZ scale `(0.5, 0.5)` for two-meter patches. Their shared seam samples identical texture positions, tint and water-depth coloring. The cliff material's `cliff_surface` branch uses the source `wall.jpg` green/UV mask to keep the irregular grass/soil border; soil and deeper cliff retain their original texture and underwater fade. No fixed linear-RGB normalization is used. Lobby material setup shares these grass settings while clumps keep authored UVs; shoreline coloring, wind and shadows remain. The generator targets the fixed original lobby palette `(0.46, 0.62, 0.32)`, avoiding feedback from the material's tint multiplier. Actual rendered continuity requires user review. The current camera remains authoritative.

Additional clumps use `water_yang/grass1.fbx` at target density `1.6` per cell surface area. They copy the full actual bases of the 43 authored clumps: facing, lean and scale, with no extra random yaw. The authored appearance retains its vertical factor of `1.65`, from a stored original basis on every rebuild. Its lean is about 35–59 degrees from vertical and growth-axis length about 0.47–0.70m. New clumps receive no additional height multiplier. The sampler checks the posed mesh AABB and wind margin against the grass surface, so accepted counts can decrease near cliffs. Original mesh coordinates let the shared lobby wind bend local +Z tips while pinning the roots. `Terrain/Flowers` and `Terrain/Grass` are separate MultiMesh batches with explicit bounds. No per-clump scripts or materials are created. Grass fill and outline use the lobby's `0.08` wind strength and waveform, driven by Godot's `TIME` through `grass_wind_use_engine_time`; the default false preserves the lobby clock. `tests/terrain_foliage_check.tscn` checks five layouts; appearance is reviewed by the user.

Gameplay directional shadow opacity is `0.55`, increased from `0.25`. The main scene's separate upper-left `TreeShadowDecor` sprite is hidden because it added another shadow image over the real tree shadows and made that area darker than its neighbors. All gameplay trees keep their actual shadow casting; ambient light, direct light color/energy, camera and cat materials are unchanged. Lobby shadow settings and its decorative sprite remain unchanged. Rendered shadow appearance requires user review.

Gameplay now uses one directional shadow map (`directional_shadow_mode=0`) instead of cascades whose boundary at about 78.85m crossed cat geometry. Shadow range is 110m with fade starting at 104.5m, beyond the board. Direction, bias, opacity, camera and cat materials remain unchanged. `tests/board_path_shadow_separation_check.tscn` checks real shadow casting, receiver separation and the board's fade margin; resolving the reported visual cutoff still requires user review.

The floor uses a local albedo tint `(0.98, 0.87, 1)` to compensate for the different lighting. In the user's 2026-11-14 15:20 comparison screenshot, two unobstructed floor regions averaged approximately `(253, 246, 116)` in Water Yang and `(248, 213–214, 117–118)` in the source (sRGB, 0–255). The floor texture bytes and texture import parameters match the source; its original material tint is white. This is a screenshot-based adjustment, not confirmation of a rendered color match. Standard lighting and shadow reception are retained; global lighting, camera, and cats are unchanged.

The floor material's `next_pass` draws thin, antialiased brown lines at each tile's UV edges using `terrain_floor_grid.gdshader`. Each existing plane represents one logical movement cell, so the lines follow `grid_to_world()` placement and board fitting automatically. The shaded floor material is retained beneath the transparent lines. Normal depth testing lets cats, holes, and raised terrain cover the lines; no geometry, colliders, or gameplay rules are added.

The source level layouts are retained for provenance only. **They are not applied.** Water Yang's current stage files, playable grid, cat/hole/obstacle placements, camera transform/projection/framing, cat movement, matching-hole rules, gimmicks, and stage progression remain authoritative.

Checks use Godot 4.7.2 headless. Rendered appearance must be reviewed by the user; data checks do not establish visual equivalence with the source project.
